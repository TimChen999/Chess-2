# Stage design tooling

All stage-generation code and design docs for Chess-2 live here. The output
target is [godot/assets/sprites/tiles/](../../godot/assets/sprites/tiles/)
for tile pairs and [godot/assets/sprites/ui/](../../godot/assets/sprites/ui/)
for stage-specific frames and backdrops.

A "stage" in this project is the visual environment of the chessboard:
the tile texture pair, optional border frame, optional viewport-wide
backdrop, and (for some stages) gameplay hazards. The first two stages
(`classic`, `moon`) shipped as a single 64x64 tile pair each, no frame
override, no backdrop. The pattern documented here is for **richer
themed stages** — multi-variant tiles, NinePatch borders, tiling
backdrops — generated via PixelLab and assembled by Godot's existing
primitives.

## Files

| File | Role |
|---|---|
| [medieval.md](medieval.md) | Generation plan for the `medieval` stage (4-tile variant set, carved-wood NinePatch frame, stone-floor backdrop). Specifies prompts, PIL reliability passes, Godot wiring. |

Per-stage Python scripts (e.g. `gen_medieval.py`) land alongside the
markdown plan when the stage is implemented, mirroring how
[../sprites/](../sprites/) keeps `gen_sprites.py` next to the prompts
it embeds.

## Pattern

Every themed stage follows the same three-part structure:

1. **Atoms** — single repeatable PNGs generated by PixelLab pixflux
   (one tile per variant, one frame atlas, one backdrop tile). Never
   ask PixelLab for "the grid" or "the whole board"; ask for a single
   16x16 / 64x64 / 128x128 unit and let Godot duplicate it.
2. **PIL reliability pass** — dimension asserts, opacity asserts,
   edge-wrap seam fixes, cross-variant color clamps. PixelLab does not
   guarantee these; the post-pass is what makes the assets reliable.
   Each script writes `_inspect_<stage>_*.png` visual-assertion images
   that show the atoms tiled at scale so seams and joinery can be
   eyeballed before shipping.
3. **Godot wiring** — extend
   [SpriteFactory.gd:218-231](../../godot/engine/SpriteFactory.gd#L218-L231)
   to load the new stage's atoms, plumb a variant index where multi-tile
   variants exist, and switch GameScene's frame / backdrop render path
   on `state.config.stage`. The stage list in
   [MainMenu.gd:75-80](../../godot/scenes/MainMenu.gd#L75-L80) gains an
   entry per stage.

## Cost

PixelLab pixflux call per atom; a typical themed stage is 4–8 atoms,
i.e. low single-digit cents per regeneration. Cache-on-seed in
`_pixellab_cache/` (mirrors [../sprites/_pixellab_cache/](../sprites/_pixellab_cache/))
makes prompt-tweak iterations free for the post-pass and chargeable
only when the prompt or seed actually changes.

## Adding a new stage

1. Drop a `<stage>.md` design doc in this folder following
   [medieval.md](medieval.md) as the template.
2. Add a `gen_<stage>.py` script alongside it.
3. Add the stage entry to `tile_texture_for_stage` in SpriteFactory and
   to the stage picker in MainMenu.
4. If the stage has hazards (cf. moon's debris in Rules.gd), wire those
   in `Rules._tick_stage_hazards`.
